**Aptos swap infrastructure**

This headless module quotes and validates wallet-held APT → Circle-native USDC on Aptos mainnet. It contains no screens, Decibel deposits, wallet secrets or funding orchestration.

`SwapProvider` returns a `ValidatedSwapPlan`. The Panora adapter calls Flare's authenticated worker, verifies the requested amounts and assets, validates the deployed router schema, and encodes the payload through the pinned Kaptos dependency. The payload hash must match the worker's independent Aptos SDK encoding. Frozen payload bytes bind review, simulation and signing to the same route.

The initial policy supports exact input and exact output, one FA withdrawal, direct routes through APT/USDC, explicit slippage from 1 to 100 basis points, a quote lifetime of at most 30 seconds, and zero provider fees. Unknown schemas, assets, fee multipliers or output protections fail closed. Supporting another provider or widening these limits requires a reviewed adapter and fixtures, rather than weakening the executor.

`validateEffects` checks the owner's net APT debit and USDC receipt using primary-store events. The app additionally reserves the full gas limit before signing. This is a simulation check; the on-chain router limits remain the execution bounds.

The application integration lives in `:venue-decibel` behind `:shared`'s `SwapRepository`. `AptosSwapRepository` handles owner authorization, profile binding, retention of executable quotes, and durable operation history. The pending transaction journal is written before submission, while the separate versioned DataStore record retains final results and both the original sponsorship reference and confirmed hash. Uncertain outcomes can only be reconciled. A fresh process cannot execute an old in-memory quote.

`:aptos-transaction` holds the execution mechanics shared with the Decibel SDK. It accepts payloads and policy callbacks and owns no keys or storage. Flare's `AptosSubmissionGate` serializes swap, Decibel and fee-top-up authorization. The shared module imports no chain SDK.

The companion worker provides `/swap/quote` and accepts the quote's signed authorization on `/gas/sponsor/owner`. Worker commit [`735557c`](https://github.com/emeieiron/decibel-worker/commit/735557c) enables quotes with `SWAPS_ENABLED=true` and a server-side `PANORA_API_KEY`; Panora's documented public key is sufficient. Sponsorship uses the existing Gas Station resource key and requires the upstream policy to permit the verified router. Quoting and self-paid execution do not depend on sponsorship: a definite rejection offers payment with the user's APT, while an uncertain submission must be reconciled first.

The Transfer sheet consumes this contract through `FundingSwapController` in `:shared`. With zero wallet USDC it offers an APT amount choice; with an entered transfer amount above the USDC balance it requests only the exact shortfall. The optional swap repository binding gates this feature, leaving other venues' funding behavior intact. A confirmed swap refreshes exact wallet balances and returns to the transfer form with its amount retained. Deposits require their own confirmation and authorization. Reopening the sheet restores unresolved swaps and offers status reconciliation rather than another execution.

`fundingCapacity` reads exact APT and USDC balances and retains a gas budget for both the swap and the following deposit even when sponsorship is expected. Kaptos resolves the current gas price through its unsigned coin-transfer builder; this fee probe is never simulated, signed or submitted. Capacity is refreshed before quoting and execution, and USDC is reread before a deposit. Failed balance reads remain unavailable rather than becoming a zero balance. The amount field and quote share one editor. Input is debounced for 600 ms; obsolete requests are cancelled and late responses cannot replace newer input. Quotes renew before expiry only while the route is visible. Editing, closing, backgrounding or changing profiles cancels quote work. Transient quote failures retry automatically with delays of 2, 4, 8, 16 and at most 30 seconds; invalid amounts and insufficient funds do not start retry loops. Authorization pins one current quote and pauses refresh until its execution finishes. The sheet keeps a top-left back action, shimmer quote values and one bottom action.

Verification uses captured public exact-input and exact-output quotes, the deployed router ABI, independent payload hashes, malformed-route tests and simulated transaction execution. Quote fixtures contain no private keys. The signing and restart tests run on the iOS simulator, following the repository's existing native runtime tests; Android host tests cannot load the chain SDK's JNI library. Live exact-input and exact-output quotes were also verified through `https://api.mcxross.xyz` with an unfunded temporary owner wallet; its session was revoked afterward. No swap was submitted. Mainnet execution with a funded wallet remains a separate release check.

The quote envelope includes worker `issuedAtMs` and `expiresAtMs`. The adapter bounds their difference to 30 seconds and counts that remaining lifetime from the local request start, conservatively deducting request time without assuming synchronized device and worker clocks. `ValidatedSwapPlan.expiresAtMs` retains the original worker timestamp for transaction construction; `localExpiresAtMs` controls retention, review and signing. The worker still enforces the original expiry on sponsorship. A definite sponsorship rejection keeps the explicit gas fallback through automatic quote renewal and self-pay progress; renewal never submits a transaction. Editing the amount or leaving the editor clears that offer.

Panora may choose a legacy coin route for a small amount even when a larger amount uses FA routes. The worker retries unsupported coin-type routes through Hyperion under the same provider deadline and applies the original validator to the replacement. No payload or route changes occur after a quote has been authorized.

Quote preparation has a 20-second deadline. Restoring the trading session after an owner quote is best effort with a two-second deadline; failure does not prevent delivery of a validated quote, and the next trading action can renew that session. These deadlines do not wrap transaction submission.


Swap quotes now include a network-fee plan selected before transaction authorization. The repository checks the worker's owner-only `/gas/sponsor/swap-availability` policy, builds and simulates the selected transaction, verifies effects and gas bounds, then retains its unsigned bytes with the quote. Preparation invokes no transaction signer, biometric confirmation or submitter. Confirmation reuses those bytes and checks wallet, profile, visit, balance and expiry before fresh owner authorization. The UI shows either coverage by Flare or an APT estimate before enabling Swap; missing or incomplete fee plans cannot execute. The fee plan records an estimate and a maximum reserve, and never silently changes a reviewed self-paid swap into a sponsored transaction.

Sponsorship is opt-in with the worker's `SWAP_SPONSORSHIP_ENABLED` deployment policy. The current deployment disables it after the observed upstream HTTP 404. Missing configuration, a failed or stalled availability read, or an active rejection cooldown selects user-paid gas before signing. This availability check is advisory: the published Geomi SDK exposes sign-and-submit without an unsigned eligibility/reservation API. An unexpected definite rejection may still offer explicit self-pay, while uncertain outcomes retain the existing reconciliation rule. Existing Decibel commands continue to use their original sponsorship behavior; the prepared-transaction API is reusable by other consumers.
